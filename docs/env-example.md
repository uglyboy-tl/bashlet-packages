# env.example 规范

每个包可以有 `packages/<包>/env.example`：给使用者的本地配置模板，复制成 `.env` 即用。
本文件是硬规范，两个样板是 `packages/dig/env.example` 与 `packages/imagine/env.example`。

## 运行时事实

规范建立在这些事实上，改动前先确认它们还成立：

- 运行时不读 `env.example`。使用者把它复制成 `packages/<包>/.env`（根 `.gitignore` 已排除，
  因为含密钥）。
- 入口在 `source .../import.sh` 之后、`import` 之前调用 `.env`，所以本文件只能设环境变量，
  不能调模块函数；`core/log` 的变量（`_LOG_LEVEL` 等）也因此能在这里设。
- 构建出的单文件会加载同目录 `.env`（入口声明 `# build:keep-env`），落点是 `<skill>/scripts/.env`。
- `: "${VAR:=值}"` 只在变量未设或为空时赋值，因此**环境里已设的非空同名变量优先于本文件**。

## 结构

分区固定，按序出现，缺哪类跳过哪类：

| 分区 | 含义 |
| --- | --- |
| 头部 | 逐字固定的说明块（见下） |
| 必需 | 缺了核心能力不可用 |
| 至少配一家 | 互斥多选一，配一家即可 |
| 可选 | 缺了只是某项能力或稳定性打折 |
| 附：回退来源 | 也能从文件或其他工具读到，不必写在这里 |
| 构建 | 只有 `tools/build` 用得上 |

## 头部块

逐字固定，只把 `<包名>` 换成包名。位于文件最开头，之后空一行再接第一个分区。

```sh
# <包名> 的本地配置模板 —— 复制成 .env 再填值
#
#   cp packages/<包名>/env.example packages/<包名>/.env
#   chmod 600 packages/<包名>/.env        # 里面有密钥，别留 644
#   $EDITOR packages/<包名>/.env
#
# 装成 skill 后：放在产物旁边，即 <skill>/scripts/.env（入口声明了 `# build:keep-env`，
# 构建出的单文件会加载同目录的 .env）。
#
# 加载时机：在 `import` 之前 source，所以也能在这里设 core/log 的变量。
# 优先级：环境里已设的非空同名变量 > 本文件。
# 写法：所有条目都是 : "${VAR:=值}"，值填在 := 后面；留空 = 不设。
#       写成 VAR="..." 会反过来覆盖环境变量，别这么写。
#
# 分区顺序固定：必需 → 至少配一家 → 可选 → 附：回退来源 → 构建。缺哪类就跳过哪类。
# 每个条目：先说是什么，再说去哪拿，最后说缺了会怎样。
```

## 分区格式

分隔线只占一行，必须带「缺了会怎样」这类信息，不写「可选配置」这种空话：

```
# ───── <区名> · <一句话说明> ─────
```

分隔线前后各空一行。分区内还可以分子组，用不带分隔线的注释：

```
# —— <子组名> ——
```

## 条目格式

凭证类（默认不注释，值留空等使用者填）：

```
# <一句话作用>。取：<在哪拿>；缺了 <具体影响>。
: "${VAR:=}"
```

调优类（默认整行注释，示例值写在 `:=` 后）：

```
# <一句话作用>（默认 <值>）。<什么情况才需要改>。
# : "${VAR:=<示例值>}"
```

规则：

- 变量行一律 `: "${VAR:=...}"`，值只填在 `:=` 之后。写成 `VAR="..."` 会覆盖环境变量，禁止。
- 注释行宽 ≤ 100 显示列（含行首 `# `，CJK 按 2 列算）；URL 与示例值实在拆不动的可以超出。
- 凭证类必须写清「取」与「缺」；调优类必须写清「默认值」与「何时改」。
- 条目之间空一行；顺序按重要性从高到低，同家/同主题的变量相邻（如两个 `CLOUDFLARE_*` 不拆开）。
- 同一个变量名只出现在一个分区里。

## 不收哪些

`env.example` 是给使用者的入手清单，不是变量全表：**用户需要主动决策的才收**（凭证、资源路径、能力开关）；
**默认值对所有场景都够用、只在排查或上游异常时才动的不收**。

这类变量在代码里带默认值，`grep -rn 'VAR:-' packages/<包>` 能找到。

## 检查清单

- [ ] 一组 grep 对齐：文件里每个变量在代码里确实被读，代码里面向用户的变量在文件里都有
      （`grep -rnE ': *"\$\{[A-Z_]+:=' packages/<包>` 对照 `VAR:-` / `VAR:=` 默认值）
- [ ] 每条都说清了「取」或「默认值」
- [ ] 每条都写了「缺了会怎样」，具体到报错文案或降级行为
- [ ] 匿名调优变量没漏（这类最容易只活在代码注释里）
- [ ] 复述的代码事实（模型名、默认值、默认条目数）与代码一致 —— 这类最易漂移：
      改 `PROVIDER_DEFAULT_MODEL` / `registry.toml` / `_DIG_*` 默认值时，同一提交里回改 env.example
- [ ] `env.example` 里没有真实密钥
