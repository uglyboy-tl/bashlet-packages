# 包内文档平铺，只把 ADR 独立成目录

包内 `docs/` 有两类内容：需要单调编号、写下来就不再改的决策记录（ADR），和会随实现更新的设计与资料。
ADR 独立成 `docs/adr/`——编号即顺序，平铺会被当成普通文档顺手改写；设计与资料数量少、更新频繁，
直接平铺，靠文件名表达类型。

## Considered Options

- **三层（`adr/` + `design/` + `reference/`）**：结构最正，但当前只有 5 个文件，会产生 6 个各装 1-2 个文件的目录。等文档数翻倍再拆。
- **完全平铺（ADR 也用 `0001-` 前缀）**：少一层目录，但 ADR 的不可变语义不可见，最容易被顺手编辑。

## 附带约束

以下是这套布局的命名细则，本身不构成「难回滚 + 会困惑 + 真实权衡」的决策，因此不另开 ADR：

- `docs/` 与 `references/` 下的文件名小写 kebab；约定俗成的名字（`README.md`、`CONTEXT.md`、`AGENTS.md`、`SKILL.md`）除外。
- `docs/` 下只允许 `adr/` 一个子目录。
- `references/` 是随 skill 分发的执行手册，`docs/` 是给维护者的设计与资料。
- 每个包有 `README.md`（`archive` 豁免）。
- 校验在 `tools/test` 全量时跑：命名 / README 存在 / `docs/` 子目录。
